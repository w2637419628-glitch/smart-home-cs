# 演示脚本

> 本项目无前端界面，演示用 `curl` 或 `/docs` 页面完成。
> 全程约 3 分钟，五幕。

---

## 〇、准备

```bash
# 启动
python start.py

# 确认模型是真实的（不是离线桩）
curl -s http://127.0.0.1:8100/api/status | python -m json.tool
#   → "provider": "openai:deepseek-chat"
#   如果是 "mock(离线桩)"，检查 .env

# 清空演示数据，从干净状态开始
curl -s -X POST 'http://127.0.0.1:8100/api/session/reset?session_id=demo'
```

> 建议同时开两个窗口：一个跑 curl，一个开 `http://127.0.0.1:8100/docs` 眼看请求返回。

## 第一幕 · 它不报价（30 秒）

```bash
curl -s -X POST http://127.0.0.1:8100/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"120平毛坯，想做全屋智能，大概多少钱","session_id":"demo"}' \
  | python -c "import sys,json;d=json.load(sys.stdin);print(d['reply']);print('槽位:',d['slots_filled'],'/',d['slots_total'])"
```

**预期**

- 回复里**没有任何具体金额**，而是反问户型/预算
- `slots_filled` 从 0 变成 2–3

**你可以说**

> 「我问了价格，它没报 —— 先问我房子多大。这是写死的铁律，也是店里老销售的做法。」

> 「注意返回里的 `trace`：它先调了 `recall_playbook` 取店长教过的话术，再用 `save_requirements` 把这句话里的信息记进档案。」

## 第二幕 · 它自己挖需求（40 秒）

```bash
for msg in "三室两厅" "中海城，预算3万"; do
  curl -s -X POST http://127.0.0.1:8100/api/chat \
    -H 'Content-Type: application/json' \
    -d "{\"message\":\"$msg\",\"session_id\":\"demo\"}" \
    | python -c "import sys,json;d=json.load(sys.stdin);print(d['reply']);print('槽位:',d['slots_filled'],'/',d['slots_total']);print()"
done
```

**预期**

- `slots_filled` 逐步走到 **6/6**
- 最后一轮的 `trace` 里同时出现 **`package_search` → `case_search`**
- 回复给出**区间**（约 2.5–3.8 万）+ **同小区案例** + 约勘测

**你可以说**

> 「我没告诉它要查套餐、要查案例 —— 是它自己决定的。代码里没有一句 `if 问完面积 then 查套餐`。」

> 「它给的是区间，不是总价。而且顺手给了同小区一户的实际花费。」

## 第三幕 · 它会说"我不会"（30 秒）

```bash
curl -s -X POST http://127.0.0.1:8100/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"你们能改燃气管道吗？","session_id":"t1"}' \
  | python -c "import sys,json;d=json.load(sys.stdin);print(d['reply']);print('handoff:',d['handoff'],'ticket:',d['ticket_id'])"
```

**预期**

- `handoff: true`，`ticket_id` 非空
- 回复明确说"已转给顾问"

**你可以说**

> 「这一幕最容易被忽略，但最重要：**它敢说自己不会**。」

> 「大部分 AI 客服在这里会开始编——'可以的，我们什么都能做'。一旦编了，客户到店发现做不了，这单就废了。」

> 「注意：为什么是燃气而不是弧形柜？因为铁律里授权了"常见工艺可以直接说能做"，弧形柜属于这类，它会答；而燃气涉及结构安全，必须转人工。」

## 第四幕 · 店长教一句（60 秒）★ 高潮

```bash
# ① 补答案 → 进待审
curl -s -X POST http://127.0.0.1:8100/api/tickets/12/teach \
  -H 'Content-Type: application/json' \
  -d '{"answer":"燃气管道不能私自改，得先报燃气公司审批，我们只能配合做柜体开孔和收口。",
       "note":"涉及燃气安全一律不承诺能改，先讲要报批，把边界说清楚。"}'
#    → {"ok":true,"sample_id":21,"status":"pending"}

# ② 待审状态下再问一次 —— 仍然转人工（闸门生效）
curl -s -X POST http://127.0.0.1:8100/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"你们能改燃气管道吗？","session_id":"t2"}' | grep -o '"handoff":[a-z]*'

# ③ 审核通过 —— 自动归纳总纲
curl -s -X POST http://127.0.0.1:8100/api/playbook/21/approve \
  | python -m json.tool

# ④ 看总纲变了什么
curl -s http://127.0.0.1:8100/api/summary | python -m json.tool
```

**预期**

- ② 仍然 `"handoff":true` —— **没审核就不生效**
- ③ 返回 `"summary_changed": true` + `"added": ["13. 客户问..."]`
- ④ 返回里能看到新增那条

**你可以说**

> 「店长只写了三行字，系统把它**归纳成了一条通用策略**，写进了 AI 的工作守则。」

> 「**不用重新训练模型、不用重启，下一句话就生效。**」

> 「这里还有个人审闸门：没点通过之前，这条话术是不生效的 —— 防止一句错话被 AI 学进去。」

## 翻车预案

| 现象 | 原因 | 现场怎么救 |
|---|---|---|
| 回复像模板 | 跑的是 mock 桩 | `curl /api/status` 确认 provider，改 `.env` 重启 |
| 教完没生效 | 忘了 approve | 当场补上，顺势讲"这就是人审闸门" |
| 又转人工了 | 教的问题和问的问题差太多 | 教学时用**客户原话**当问题 |
| 500 | 服务挂了 | `journalctl -u smart-home-cs -f` 看 traceback |
| 429 | 体验模式超额 | `DEMO_MODE=false` 或调高额度 |
| 槽位不动 | 上一轮会话残留 | `POST /api/session/reset` |

## 预判提问

**Q：这不就是提示词工程吗？**
> 是，也不止。提示词只是最后一层。前面有：样本沉淀、检索、人审闸门、增量归纳、状态合并（人工改写不被覆盖）、以及一个能自主选工具的循环引擎。提示词是**结果**，不是**方法**。

**Q：为什么不直接微调模型？**
> 话术一周一变，微调跟不上；而且不可解释、不能回退、错了没法当场改。这套是示范学习：教一句、审一下、立刻生效、随时可撤。

**Q：检索用的是向量吗？**
> 默认不是。默认是字符 bigram + IDF 的词法匹配，库里配了 `ARK_API_KEY` 才走真向量。这是已知短板，见 README「已知限制」第 1 条。

**Q：怎么证明它有用？**
> 现在能量化的是转人工率、命中率、需求补齐率。**成交归因是 v2 的事**，那才是最终证明。

## 极简版（30 秒，时间不够时用）

```bash
# 1. 不报价
curl -s -X POST $B/api/chat -H "$H" -d '{"message":"全屋定制多少钱","session_id":"x"}'
# 2. 敢说不会
curl -s -X POST $B/api/chat -H "$H" -d '{"message":"你们能改燃气吗","session_id":"y"}'
# 3. 教一句 → 通过 → 再问就答对
```

三句话讲完：
> 「第一，它不报价。第二，它敢说不会。第三，教一句它就会了——而且不用训练模型。」
