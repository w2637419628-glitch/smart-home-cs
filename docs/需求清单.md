# 需求清单 · 会进化的智能家居客服

> 版本 v1.0　|　状态：已实现　|　用途：钉死"做什么、不做什么、怎么算做完了"

---

## 一、背景与定位

### 1.1 要解决的问题

智能家居门店的真实痛点不是"没人回消息"，而是：

| 痛点 | 表现 |
|---|---|
| **新人接不住老销售的话术** | 客户问价，新人直接报价；老销售会先问需求。一线之差，成交率差一倍 |
| **经验跟着人走** | 销售一离职，他脑子里的套路就没了，新人从零开始 |
| **报价即事故** | AI 或新人报出精确总价，客户截图，到店对不上，纠纷 + 差评 |
| **答不上的问题没人沉淀** | 客户问"弧形柜能做吗"，新人说"我问问"，然后就没了，下次还问 |

### 1.2 一句话定位

> **不是"客服机器人"，是"把金牌销售的话术，变成新人第二天就能用的能力"。**

### 1.3 与普通 AI 客服的区别

| | 普通 AI 客服 | 本系统 |
|---|---|---|
| 目标 | 把问题答对 | **把客户往前推一格**（留资 → 勘测 → 成交） |
| 知识 | 静态知识库 | **店长持续教，系统持续学** |
| 回答方式 | 有问必答 | **信息不足先追问，没把握就转人工** |
| 价格 | 报价 | **绝不报总价，只给区间** |
| 上线后 | 效果封顶 | **越用越准** |

## 二、目标用户与场景

| 角色 | 用什么 | 关心什么 |
|---|---|---|
| **店长 / 销售主管** | 后台「教它」「待审 / 工单」 | 新人能不能按我的套路说话；教的东西有没有生效 |
| **一线销售** | 客户对话页（演示 / 辅助） | AI 说得对不对，能不能直接用 |
| **客户** | 对话页 | 别被推销、别被忽悠、能拿到实在的方案区间 |

**核心场景（本期只做这一个）**：客户在线上咨询全屋智能 → AI 挖需求 → 给方案区间 + 同小区案例 → 约免费上门勘测。

## 三、范围：做什么 / 不做什么

### 3.1 本期做（v1.0）

| # | 功能 | 验收方式 |
|---|---|---|
| F1 | **6 项需求挖掘**：场景 / 面积 / 户型 / 装修阶段 / 预算 / 小区 | 对话页进度条 0/6 → 6/6 |
| F2 | **绝不报总价**，只给区间 | 50 次提问 0 次输出精确价（有单测） |
| F3 | **套路召回**：按语义取店长教过的 top-4 话术 | 轨迹里能看到 `recall_playbook` |
| F4 | **方案检索**：按场景 + 面积匹配套餐区间 | 需求不全时工具直接报错，逼模型回去追问 |
| F5 | **案例检索**：同小区 / 同户型完工案例 | 命中时回复里出现具体小区与花费 |
| F6 | **约上门勘测**：需要手机号，生成勘测工单 | 后台「工单」出现 `survey` 记录 |
| F7 | **答不上就转人工 + 建工单** | 问"弧形柜"→ 转人工 + 工单 |
| F8 | **教学模式**：问题 + 标准答案 + 为什么这么答 | 提交后进待审 |
| F9 | **工单补充**：针对工单补答案 | 补完进待审 |
| F10 | **人审闸门**：待审不生效，通过才入库 | 待审时再问仍转人工 |
| F11 | **自动固化**：审核通过 → 自动重写总纲 → 注入提示词 | 提示词里能看到新增条目 |
| F12 | **状态合并**：店长手改的总纲不被 AI 覆盖 | 改完再归纳，改写仍在 |
| F13 | **提示词 diff**：显示这次总纲多了哪几条 | 后台「套路总纲」页 `+` 行 |
| F14 | **合规拦截**：违禁词 / 精确报价 | 轨迹里出现 `compliance_blocked` |
| F15 | **Agent Loop 护栏**：步数 / 超时 / 重复调用 / 打转提前收尾 | `_test_guard.py` 通过 |
| F16 | **双模型后端**：真实模型优先，失败降级离线桩 | 断网仍可演示 |

### 3.2 本期明确不做（同样重要）

| 不做 | 为什么 |
|---|---|
| ❌ **精确报价** | 一次价格事故足以让项目叫停 |
| ❌ **承诺工期 / 承诺"绝对稳定"** | 兑现不了，是投诉源 |
| ❌ **多租户 / 登录 / 权限** | 单店演示版，做了是浪费 |
| ❌ **图片消息**（客户发户型图） | 本期只处理文本 |
| ❌ **流式输出** | 真实模型 2–4 秒，体感可接受 |
| ❌ **成交归因 / A-B 灰度** | 属于 v2，见第六节 |
| ❌ **语音、电话、企微接入** | 渠道对接属于集成层，不是本期重点 |

## 四、业务铁律（写进代码，不是写进 PPT）

这 5 条是硬约束，**由数据结构或代码保证，不靠提示词自觉**：

| # | 铁律 | 怎么保证 |
|---|---|---|
| R1 | **绝不报精确总价** | `packages` 表没有 `total_price` 字段；`compliance` 正则拦"总价：X 元" |
| R2 | **报价前必须问齐 6 项** | `package_search` 发现缺项直接返回 `error`，模型拿不到数据 |
| R3 | **不承诺工期、不承诺绝对稳定、不贬低同行** | 提示词第 4 层合规红线 + `COMPLIANCE_BANNED` 词表 |
| R4 | **没学过的不许编；但常见技术按铁律授权可以说"能做"** | 检索未覆盖时：泛化能力放行（铁律第 6 条），硬承诺（具体工期/保证/绝对化）由 `_HARD_CLAIM_RE` 拦下并转人工；涉及结构安全一律转人工 |
| R5 | **教的东西必须审核才生效** | `playbook.status` 过滤，`pending` 不参与检索 |

## 五、数据模型（7 张表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `playbook` | question / answer / note / source / **status** / scene / vector | 话术样本，`status` 是审核闸门 |
| `settings` | key / value | `business_directive` 铁律、`playbook_summary` 总纲、`..._prev` 上一版、`summary_upto_id` 增量游标 |
| `leads` | 6 个槽位 + phone + **stage** | 客户档案；`stage` 是客户阶段（inquiry/qualified/survey_booked） |
| `tickets` | **kind** / question / context / status | `ticket`=转人工，`survey`=勘测预约 |
| `packages` | price_min / price_max / includes / excludes / duration_days | **只有区间** |
| `cases` | community / layout / area / cost_min / cost_max | 完工案例 |
| `metrics_log` | playbook_hit / handoff / slots_filled / tools_used | 埋点 |

> ⚠️ 注意：`leads.stage` 是**客户阶段**，`leads.stage_reno` 才是**装修阶段**。这两个不能混。

## 六、验收标准

### 6.1 功能验收（可自动测）

```powershell
python _test_guard.py   # 护栏
python _dev_test.py     # 七幕
python _smoke_test.py   # 七幕（HTTP）
```

| # | 标准 | 判定 |
|---|---|---|
| A1 | 一上来问价，**不出现任何精确数字** | 首轮回复无 `X元/X万` |
| A2 | 需求从 0/6 补齐到 6/6，**每轮只问 1–2 项** | 进度条单调递增 |
| A3 | 需求齐后**同一轮**串起 `package_search` + `case_search` | trace 里两种工具都出现 |
| A4 | 一次对话至少出现 **3 种不同工具** | trace 统计 |
| A5 | 没学过的 → `handoff` + 建工单 | `handoff=True` 且 `ticket_id` 非空 |
| A6 | 待审样本**不生效** | 教完未审核，再问仍 `handoff=True` |
| A7 | 审核通过 → 总纲变化 → 提示词里出现新条目 | `summary != before` 且 `异形 in prompt` |
| A8 | 教完再问**直接答对** | `handoff=False` 且回答含知识点 |
| A9 | 重置会话后需求归零 | 进度条回 0/6 |

### 6.2 体验验收（人工）

- 对话轮次 ≤ 8 轮可以走完"问价 → 给方案 → 约勘测"
- 真实模型下单轮响应 ≤ 5 秒
- 所有状态变更都能通过 GET 接口立即查到（无缓存延迟）

## 七、非功能要求

| 项 | 要求 |
|---|---|
| **性能** | 单轮 Loop ≤ 8 步、≤ 45 秒；超时降级转人工 |
| **可用性** | 真实模型不可用（没 key / 断网）自动降级 mock，**演示不中断** |
| **可观测** | 每轮 trace 完整，可追溯"模型看到了什么、决定了什么、工具返回什么" |
| **可回退** | 总纲可手改；样本可驳回；`data.db` 可删重建 |
| **合规** | 违禁词 / 精确报价 / 站外导流 / 承诺类表述四类拦截，留痕可审计 |
